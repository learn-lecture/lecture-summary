# 리다이렉션

* 301, 308 사실 근본적인 것은 똑같음 - 영구적 리다이렉션
  * 301은 리다이렉션 시 GET으로 본문을 버림
  * POST 리다이렉션 시 본문을 다시 요청해야 됨
  * 308은 본문과 메서드를 유지함
  * 실제로는 uri가 바뀌었다는 것은 내부 구조도 바뀌었을 확률이 높음
    * 그래서 301로 그냥 전체 바뀐 정보를 반환해주는 경우가 많음
* 302, 303, 307 마찬가지 - 일시적인 리다이렉션
  * 302 Found
    * 브라우저에 따라 본문을 제거할 수 있고, 제가히지 않을 수도 있음.
    * 리다이렉션 시 메서드는 GET으로 바뀔수도 있고, 바뀌지 않을 수도 있음.
  * 303 See Other
    * 브라우저에 따라 다르게 구현한 302의 한계를 해결
    * 무조건 GET, 본문 버림
  * 307 Temporary Redirect
    * 마찬가지 한계 해결
    * 요청 메서드와 본문을 유지
  * 실제로는 302를 많이 쓴다고 한다.
* 리다이렉션은 언제 쓸까?
  * 같은 요청으로 인해 Post 요청이 두 번 발생할 때, 방지하기 위함
  * 멱등성 관리 - PRG 패턴
  * 개인적으로 생각했을 때, Client-Server 구조라면 API 리다이렉션 외에는 안쓸듯
