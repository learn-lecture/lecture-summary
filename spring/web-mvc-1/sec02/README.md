# WEB SERVER, WAS

* 정적 파일을 서빙하는 역할 공통
* WAS는 동적 처리도 가능
  * 애플리케이션 로직
  * 톰캣, JETTY, Under Tow
* Web Server, WAS를 분리
  * 오류와 같은 정적 파일 렌더도 불가능
  * Application Logic만 집중 가능
  * 정적 파일 제공하는거에 비용 낭비 안함
  * 각 각 스케일 아웃 가능

# 서블릿

* 기존 http 스펙에 대해 처리하는 과정을 편하게 다 처리해둠
  * 파싱 등, HttpServletRequest, HttpServletResponse

## 서블릿 컨테이너

* 서블릿 객체의 생명주기를 관리 - 생성, 초기화, 호출, 종료
* 서블릿 객체를 싱글톤으로 관리
  * 공유변수 사용 관리 
* 멀티 스레드 처리 지원

## 멀티 스레딩

* 동시요청 처리 가능
* 컨텍스트 스위치 비용, 리소스 관리 어려움 등 단점도 있음
* 대신, 개발자는 멀티 스레드를 고민하지 않아도 됨.
  * 싱글톤, 빈에 대해 주의해서 사용

## 쓰레드 풀

* 요청마다 쓰레드 생성의 단점 보완
* 미리 생성해두고, 반납하면서 생성 비용감소, 기존 요청을 안전하게 처리 가능
